SteamYard Request Flow

How requests are processed from client to response

Request lifecycle: Every incoming request follows the same path: authentication verification, endpoint routing, cache lookup, and conditional API queries. The server implements exponential backoff retry logic for failed external API calls and caches all results to minimize quota consumption.
Step 1

Client makes POST request

Client sends an HTTP POST request to the `/mcp` endpoint with the tool name and parameters, including the bearer token in the Authorization header.

Step 2

MCP server validates auth

Server checks that the bearer token matches the configured MCP_AUTH_TOKEN. Invalid tokens are rejected immediately with a 401 response.

Step 3

Route to correct tool

The request body specifies which tool to invoke. Server matches it to one of the four tools: get-owned-games, get-game-dlc, compare-dlc-prices, or price-history.

Step 4

Check response cache

Before making external API calls, server checks if the exact query result is already cached. Cache keys include the tool name and all parameters. Cache hit saves API quota and latency.

Step 5

Query external API (cache miss)

If the cache misses, server makes the actual HTTP request to Steam, ITAD, or CheapShark. Includes exponential backoff retry logic if the API is temporarily unavailable.

Step 6

Return JSON response

Server parses the external API response, caches the result, transforms it into MCP protocol format, and returns it to the client as structured JSON.
